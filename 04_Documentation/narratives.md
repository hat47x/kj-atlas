# Narratives

対象読者: kj-atlas のカード、島、関係性から説明文や要約を作る利用者、レビュー担当者。

目的: ナラティブ生成・確認の基本的な使い方と、安全なレビュー観点を示します。

範囲外: 自動公開、AI 出力の自動採用、組織固有の文章承認フロー。

## ナラティブとは

ここでのナラティブは、カードや島の関係を人間が読みやすい文章にしたものです。正解を自動生成する機能ではなく、理解を助ける下書きとして扱います。

## 基本フロー

1. 対象ドキュメントを開く。
2. 要約したい島、カード群、関係を選ぶ。
3. ナラティブ生成またはチェックを実行する。
4. 出力を人間が確認する。
5. 必要なら修正し、採用・保留・破棄を判断する。

## レビュー観点

- 元のカードにない断定が追加されていないか。
- 少数意見や曖昧さが消されていないか。
- 未レビュー情報を確定事実のように扱っていないか。
- 個人情報や秘密情報が出力に混ざっていないか。
- SafeMode の前提を崩していないか。

## AI 出力の扱い

AI が生成した文章は提案です。人間が確認するまで、レビュー済み・確定済みの扱いにしません。自動採用や自動公開は避けてください。

## LLM が無効な場合

既定の `KJ_ATLAS_LLM_PROVIDER=none` では、AI 生成は disabled として失敗します。これは安全な既定値です。LLM を使う場合は [local_llm_ops_guide.md](local_llm_ops_guide.md) と [security.md](security.md) を確認してください。

## 記録する情報

ナラティブを運用で使う場合は、次を残すと後から確認しやすくなります。

- 対象ドキュメント ID
- 対象カードまたは島
- 生成日時
- provider 種別
- 採用、保留、破棄の判断
- 人間の修正内容

秘密情報や prompt 全文を保存する必要がある場合は、組織の情報管理ルールに従ってください。
