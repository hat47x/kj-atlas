# Issue: DOGFOOD-METRIC-01 自律性昇格ゲートの指標が自作スクリプトの出力であり、測定器を弱めることで満たせてしまう

- Type: Process

- Priority: P2
- Owner: Maintainer
- Scope: `AGENTS.md` §1.3, `01_Plans/dogfood/README.md`, `03_Implement/backend/scripts/check_design_consistency.py`, `03_Implement/backend/scripts/check_contract_drift.py`

## 課題

`AGENTS.md` §1.3 の自律性昇格条件は定量化されており、これ自体は 2026-08-11 のドッグフーディングで「間接参照では永遠に満たされない」という指摘に応えた**正しい改善**である。しかし定量化の結果、ゲートの成否が**本プロジェクト自身が書き、いつでも変更できるスクリプトの出力**に依存する構造になった。

L2昇格条件の3つが該当する。

| 条件 | 測定器 | 測定器を弱めると |
|---|---|---|
| ① 設計整合警告50件未満 | `check_design_consistency.py` | 検出対象を狭めれば満たせる |
| ② 三要素検証適用ADR 10件以上 | ADR本文の節の存在 | 節を書けば満たせる（内容の質は測っていない） |
| ③ 実API検証2操作以上 | `ai_eval_results.md` の手記録 | 記録すれば満たせる |

**これは仮説ではなく、既に1件実際に起きている。** `DX-DESIGN-CHECK-01` のとおり、条件①の「139→1」の一部は api.md への追記（正しい対応）だが、同時に入った正規化が実装42ルート中26本を区別不能にしており、**検出能力の低下によって数値が下がった分**が含まれる。

なお②については、全76 ADRの節の内容を抽出して確認したところ、各ADR固有の次元間制約が具体的に書かれておりテンプレ埋めではなかった。③のサンプル数（10件・4件）も記録上に明示されている。**現時点で実害が確認できたのは①のみ**である。本issueは指標全体を疑うものではなく、**同じ失敗が再発しうる構造**を扱う。

## 論点（人的判断が必要な理由）

「測定器を信用しない」を徹底すると外部監査が要り、個人OSS（`ADR-0039`）の運用規模を超える。一方で何もしなければ、指標は「プロダクトの状態」ではなく「測定器の状態」を測り続ける。**どこまでの担保を、どのコストで置くか**は保守者判断とする。

選択肢:

- **案A: 測定器ごとに「能力カナリア」を置く。** 検出器が検出できるはずの既知の陽性例を固定し、検出できなくなったらCIを落とす。`DX-DESIGN-CHECK-01` AC-3 がこの形式。コストは各測定器につきテスト1本。
- **案B: 指標の変化と同時に測定器が変更された場合、昇格判定に使わない。** 「今回の削減のうち、測定器変更に由来する分と対象修正に由来する分」を分離して記録することを昇格判定の必須項目にする。運用ルールのみでコードは不要。
- **案C: 昇格判定を、スクリプト出力ではなく成果物で行う。** 例: 「警告50件未満」ではなく「api.mdに全実装ルートが記載されている（別の独立した突合で確認）」。指標の意味は明確になるが、突合手段を別に作る必要がある。
- **案D: 現状維持とし、四半期判定時に人間が測定器の変更履歴を確認する運用とする。**

案Aと案Bは排他ではなく、併用が自然と考える。

## 影響

現時点で L2 は昇格済み（`ADR-0075`）であり、その根拠の一部が①に依存している。本issueは**昇格の取り消しを求めるものではない**——②③は妥当であり、①も api.md 追記という実質的な改善を含むため、昇格が全面的に不当とは言えない。ただし L3 昇格条件はより重い（コード生成成功率80%以上・全管理面の運用開始・週次運用3ヶ月継続）ため、**L3判定の前に測定の担保を決めておく**必要がある。

## 補足

- 発見経緯: ドッグフーディング状況確認の一環で、L2昇格を支える4指標の妥当性を検証した際に発見した。
- ドッグフーディングの記録自体は誠実である。`codegen_results.md` は「これは骨格生成成功率であり、L3の『設計→実装→テストの自律実行』を完全には表さない」と自ら限界を明記し、一度計上した成功例を重複コード生成として不採用へ訂正している。本issueが指すのは記録の姿勢ではなく、**指標と測定器が同一主体の管理下にあるという構造**である。
- ドッグフーディングは「摩擦を見つける仕組み」として機能している（改善点12件が記録され、すべて対応済み）。本issueはその仕組みが**自分自身の測定を検証する経路を持たない**という一点に限定される。
