# 継続dogfood R13 — AI入力IRの経路漏れをどう防ぐか

- Date: 2026-09-03
- Scope: 日常開発の自己分析と、その場で実施できる再発防止。Case 001〜003の統制比較には含めない。
- Question: `AI-IR-PROJECTION-01` をStage 5へ進めるとき、AI入力IRを通るべき経路の全体像を、手作業の棚卸しに頼らず保てるか。
- Canvas: `doc_kj_atlas_dogfood_r13.json`
- Result class: 継続dogfoodの内部所見と実装上の非後退検査。第三者価値実証や認知比較結果の代替証拠ではない。

## 1. このラウンドを始めた理由

R12では、KJ Atlasの一次価値から現在の未完事項を比較し、人間が残した根拠、異論、保留、関係をAI入力で落とさない `AI-IR-PROJECTION-01` をP1のまま進める判断が確認された。

そこでR13では、その判断を説明するだけで終えず、実際にStage 5へ進むため現行コードを読み直した。

`AI-IR-PROJECTION-01` はStage 1〜4を完了している。現行11件の `LLMRequest` 呼出しのうち、次の4タスクは `inputs=` にLLM入力IRを載せている。

- `detect_contradiction`
- `suggest_card_groups`
- `generate_narrative`
- `re_layout`

残る7タスクはStage 5の未移行経路である。

- `check_narrative`
- `suggest_merges`
- `suggest_island_summary`
- `propose_opposing_viewpoint`
- `refine_card_text`
- `suggest_document_title`
- `summarize_island_relation`

## 3. 島1 — IR移行は進んだが、経路の全体像は手作業で追っている

`AI-IR-PROJECTION-01` の起票時には、`routes/ai.py` のプロンプト構築経路を9件として数えていた。その後、2026-08-31の再実測では `routes/ai.py` に10件、`routes/ai_relations.py` に1件の計11件へ増えている。

経路が増えること自体は問題ではない。問題は、IRを経由しているかどうかを知るために、その都度コードを人手で読み直して数えていることである。

R13でもStage 5を進める前に同じ棚卸しを行った。これは、一次価値に直結すると判断した境界が、まだCI上の不変条件になっていないことを示している。

## 4. 島2 — 手作業の一覧だけでは、新しい迂回経路を防げない

人間が残した関係、根拠リンク、保留、島階層などをAIへ渡すことは、単なるprompt品質の向上ではない。KJ Atlas上で積み上げた判断をAI支援へつなぐための意味保存の境界である。

その境界について「現在は4件移行済み、7件未移行」と文書へ書くだけでは、新しいAI機能が追加されたときに自動では止まらない。9件だった経路が11件へ増えた履歴がある以上、同じことは今後も起こり得る。

そこで、`LLMRequest(...)` の呼出しそのものをASTで列挙し、各タスクを「IR移行済み」または「Stage 5の明示的な残債」のどちらかへ必ず分類する検査を追加した。

## 5. 実装 — 経路被覆をCIで固定する

追加した検査は次である。

- `03_Implement/backend/tests/test_ai_llm_input_ir_coverage.py`

このテストはFastAPIアプリ、LLM、providerを起動しない。PythonのASTだけを用いて `routes/ai.py` と `routes/ai_relations.py` を読み、全 `LLMRequest` 呼出しを列挙する。

検査する内容は次のとおりである。

1. `LLMRequest.task` は棚卸し可能な文字列リテラルであること。
2. 現行11呼出しから追加・削除があった場合、分類を更新しない限り失敗すること。
3. IR移行済み4タスクは、すべての呼出しで `inputs=` を持つこと。
4. Stage 5の7タスクは未移行の残債として明示し、`inputs=` を追加したら同じ変更でIR移行済み集合へ移すこと。

これにより、新しいAI経路を追加しただけでは静かにIRを迂回できない。また、既に移行した経路から `inputs=` を落とす退行も検知できる。

## 6. 島3 — #2817の規模評価とは問題を分ける

並行するPR #2817では、`AI-IR-PROJECTION-01` AC-10の前半として、300カード・30島の代表規模を投影している。その結果、現行 `MAX_CARDS=200` では300枚のうち100枚がモデル到達前に外れ、30島のうち10島がメンバーを失うことが確認されている。

この観察は重要であり、Stage 5を7経路へ一括展開しない理由になる。一方、R13の経路被覆とは役割が異なる。

- #2817は、**IRへ何をどこまで載せられるか**を扱う。
- R13は、**どのAI経路がIRを通っているかを見失わないこと**を扱う。

規模・token予算の判断が決まるまでStage 5の意味設計を先回りしない一方、経路被覆の検査はその結論に依存せず安全に追加できる。

## 7. 島4 — 静的検査をStage 5の代替にしない

今回のテストは `inputs=` が存在することを確認するだけである。

したがって、次のことは証明しない。

- 必要な関係や根拠がIRに十分含まれていること。
- promptがIRを正しく解釈していること。
- 人間の保留や判断をエンドポイント固有の意味で正しく守っていること。
- 代表規模で意味を落とさず収まること。

Stage 1〜4では、IR経由化と同時にエンドポイント固有の統合テストを追加し、人間の既決を決定論で守る箇所も実装した。Stage 5でも同じ原則を維持する。

つまりR13はStage 5を「完了」に近づけたのではなく、Stage 5を進める途中で全体の被覆を再び見失わないための足場を作った。

## 8. 課題の振り分け

| 観察 | 判定 | 対応 |
| --- | --- | --- |
| AI経路の棚卸しが起票時9件から再実測11件へ変化した | 再現済みの構造的摩擦 | `AI-IR-COVERAGE-01` として起票し、その場でCI検査を実装してDoneとした |
| IR移行済み4経路から `inputs=` が外れる可能性がある | 非後退リスク | AST検査で失敗させる |
| 新しい `LLMRequest` がIR分類なしで追加され得る | 将来の経路漏れ | 全呼出し数とtask集合を明示分類し、未分類追加を失敗させる |
| Stage 5の7経路は依然未移行 | 既存P1の残作業 | `AI-IR-PROJECTION-01` に残す。R13だけで完了扱いしない |
| 300カード規模でIR切り詰めが生じる | 並行するAC-10課題 | PR #2817 / `AI-IR-SCALE-01` の判断へ委ね、R13では上限を変更しない |

## 9. 今回の判断

新しい機能IssueやADRは追加しない。

検出した経路被覆の欠落は、`AI-IR-PROJECTION-01` の実装を安全に継続するための具体的な非後退課題なので、`AI-IR-COVERAGE-01` として計画文書へ残し、同じR13でテストまで実装してDoneとした。

Stage 5の実装順序やIR投影戦略は変更しない。#2817で確認された代表規模の構造損失と、その後のtoken予算・意味保存型投影の判断を確認してから、次のエンドポイント単位の移行へ進む。
