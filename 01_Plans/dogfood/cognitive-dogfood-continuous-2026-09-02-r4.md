# 継続dogfood記録 — 2026-09-02 第4ラウンド

## 位置づけ

この記録は、KJ Atlas自身を日常的な開発対象としてKJ法で検討する継続dogfoodの第4ラウンドである。

前ラウンドでは `VALUE-REALNESS-01` を対象とし、第三者による価値実証について、検証手順はすでに整っている一方、現在の律速は実際の第三者と、その人が扱える資料という外部入力にあることを確認した。

今回は、もう一つのP0である `COGNITIVE-EVAL-01` を対象とし、認知比較実験を前へ進めるために何がまだ不足しているのかを確認した。

これはCase 001〜003の統制比較そのものではない。この継続dogfoodには、比較設計、評価軸、自然発生した訂正履歴、R8/R9などの既知情報が含まれているため、A〜Dのどの比較条件にも数えない。生成AIの外部APIも使用していない。

## 今回の問い

> 認知比較実験を進めるうえで、いま不足しているのは比較設計、実験ハーネス、KJ Atlasの製品機能なのか。それとも、比較設計に関する既知情報から隔離された新規コンテキストと、C/DでKJ Atlasを実際に操作する実行環境なのか。

「まだ準備不足だから実験できない」と最初から決めず、正本Issue、凍結記録、実行計画、索引、UI操作手順、検証スクリプト群、受入条件を同じ場に置いて確認した。

## 島1 — 比較設計と実験ハーネスは揃っているが、有効な生の実行記録はまだ得られていない

`COGNITIVE-EVAL-01` はP0かつIn Progressであり、Case 001〜003をA〜Dの4条件で比較する設計を正本として持っている。

P0では、次の事項がすでに固定・検査されている。

- Case 001〜003の問い。
- 製品スナップショットとスキルスナップショット。
- A〜Dそれぞれに適用する条件。
- 条件間で共通に要求する成果。
- 製品証拠の入力一式。
- B/Dだけへ渡すスキル一式。
- C/Dだけへ渡す空の開始文書。
- 実行記録。
- 匿名化した比較資料とブラインドレビュー手順。

さらに、起動用入力、各条件の実行パッケージ、実行記録、匿名化資料には、それぞれ専用の検証スクリプトと契約テストがある。

一方、`cognitive-dogfood-index.md` が示す現在地は明確である。

> P1: Case 001 Arm C 実行可能 / 生の実行記録は未取得

`COGNITIVE-EVAL-01` の受入条件でも、3ケースすべての4条件比較、M1〜M9の観察、ブラインドレビュー、C/DでのInquiryJourney実使用などは未完のままである。

したがって、実験準備が成熟していることと、比較証拠が得られていることは分けて扱う必要がある。

## 島2 — 現在の律速は、隔離された新規コンテキストとC/Dでの実際のUI操作にある

比較設計では、各条件を独立したコンテキストで開始し、他条件の中間成果や、評価者側がすでに知っている仮説を見せないことになっている。

これは形式だけの手続きではない。

今回のような設計者側の継続dogfoodは、すでに次の情報を知っている。

- 4条件を置く狙い。
- M1〜M9の評価軸。
- Case 001で自然発生した訂正履歴。
- Case 000の回顧監査。
- R8/R9で得た内部所見。
- 観察対象としている失敗類型。

このコンテキストでA〜Dの回答を作れば、比較方法そのものに関する知識が各条件へ混入する。とくに「何を見落としてはいけないか」を知った状態では、通常チャットを用いる基準条件まで意図せず改善してしまう。

また、C/Dは単にKJ形式のJSONを成果物として残す条件ではない。KJ Atlasキャンバス上でカードを外部化し、束ね、残差や対立を見ながら構造を動かし、必要な節目でInquiryJourneyを使う。その外部表象との往復自体が比較条件の一部である。

したがって、このチャット内でJSONを代理編集しても、C/Dを実施したことにはならない。

現在、有効な実行記録を得るために不足している主な入力は、次の二つである。

- 比較設計に関する既知情報から隔離された新規コンテキスト。
- C/DでKJ AtlasのUIを実際に扱う実行環境。

## 島3 — 準備を増やすより、妥当性を保ったまま実行へ移る

ここで新しい実験スキーマ、追加KPI、別の履歴API、さらに細かな事前検証文書を増やしても、隔離された新規コンテキストと実際のUI操作がない限り、有効な比較証拠は増えない。

むしろ、準備を増やし続けると次の問題が起こり得る。

- 実験のための計測要件が製品契約へ逆流する。
- 実行担当者が実験設計について知る情報がさらに増える。
- 「実行のための準備」が自己目的化する。
- 実際の比較結果がないまま、内部整合だけが高度化する。

逆に、隔離条件を緩めれば、A〜Dらしい成果物だけならすぐに作れる。しかし、それは実行を早める代わりに比較の意味を弱める。

このため、R10では「さらに自動化すべき」という方向へは進めない。

有効な実行記録がまだないことを、KJ Atlasの製品欠陥や `cultural-substrate-weaving` の方法欠陥へ読み替える根拠もない。

## 島4 — 固定スナップショットによる比較価値と、現在のmainへの一般化限界を同時に保持する

Case 001〜003では、条件間で同じ製品状態を比較するため、製品スナップショットを固定している。

これは比較実験に必要である。実行順の途中で現在のmainへ追従すると、R7〜R9や初回価値体験の改善など、別の変更が条件間へ混入するためである。

一方、2026-09-02現在のmainは、その固定スナップショットより先へ進んでいる。

したがって、Case 001〜003で得る結果については、次の二つの読み方を混同しない。

- **妥当な読み方**: 同じ固定状態のもとで、通常文書とKJ Atlas、スキルなしとスキルありの差がどう現れたかを見る。
- **過剰な読み方**: その結果を、その後の改善まで含む現在のmain全体に対する絶対評価として扱う。

固定スナップショットは、古いから無効なのではない。因果比較のために意図的に固定している。ただし、得られた結果をどこまで一般化できるかについては、評価対象の時点を明示する必要がある。

## 課題の振り分け

| 観察 | 判定 | 対応 |
| --- | --- | --- |
| 3ケース、4条件、固定スナップショット、評価軸は定義済み | 解消済みの不確実性 | 比較設計を追加しない |
| 入力一式、実行パッケージ、実行記録、匿名化レビュー資料の検査系は存在する | 解消済みの不確実性 | 新しい実験スキーマを作らない |
| Case 001 Arm Cは実行可能だが、生の実行記録は未取得 | 既存P0の未完 | `COGNITIVE-EVAL-01` をIn Progressのまま維持する |
| この設計者コンテキストは比較条件として汚染済み | 既存境界 | 有効な実行には使わない |
| C/Dでは実際のUI上で外部表象を操作する必要がある | 比較条件 | JSONの代理編集を実走とみなさない |

| さらに事前検証を増やしたくなる | 実験計測の逆流候補 | 生の実行記録を得るまで新規ハーネス追加を原則停止する |

## 今回の判断

R10では、新しい製品P0欠陥は確認されなかった。

また、新しいADR、別Issue、`cultural-substrate-weaving` の正本変更を起こす根拠も得られなかった。

`COGNITIVE-EVAL-01` を実質的に前進させる次の条件は、事前登録された順序に従い、Case 001の隔離されたArm Cの実行記録を実際に取得することである。その後は同様に独立したD、B、Aへ進み、静的検査を通した生の実行記録だけをブラインドレビューへ渡す。

この継続dogfood自体は、その比較結果の代替証拠にはしない。
