# agent_handover — AIエージェント開発引き継ぎガイド（共通）

本ドキュメントは、kj-atlas の開発を **特定製品に依存しない AI エージェント運用**へ引き継ぐ際の実務ガイドである。

- `AGENTS.md`: ナビゲーション（読む順番・Project Map）
- `system_prompt.md` / `domain.md`: 行動規範・概念制約
- 本書: 実行戦略、完了定義、継続進行、停止/復旧ルール

> 位置づけ: 本書は「アプリ利用者向け運用」ではなく、**AI開発運用ポリシー**であるため `00_Prompt/` に配置する。

---

## 1. 目的と完了定義

### 1.1 目的

- 人間中心の開発から AI エージェント中心の開発へ、安全性を維持して移行する。
- 仕様逸脱を抑制しつつ、継続実装・継続検証・継続ドキュメント更新を可能にする。
- safeMode 既定ON・漏えい防止（share/export）を維持する。

### 1.2 引き継ぎ完了定義（DoD）

以下を満たした時点で引き継ぎ完了とする。

1. AIエージェントの作業入口（Read Order）が一意に共有されている。
2. タスク開始時に Scope / Acceptance / Checks を先に固定する運用が定着している。
3. 変更順序（00〜02整合 → 03実装 → 04文書同期）が守られている。
4. safeMode・漏えい防止違反がレビューまたはCIで差し戻し可能である。
5. 停止基準・復旧手順・人手エスカレーション条件が明文化されている。

## 3. 実行戦略（単一タスク原則）

### 3.1 1タスクの固定順序

1. Scope固定（Docs / Frontend / Backend / Schema）
2. Acceptance固定（3〜7項目）
3. 実装（上位層整合を確認してから）
4. 検証（テスト / lint / 差分確認）
5. 文書同期（関連ドキュメントを同時更新）
6. 完了判定（Acceptanceを全照合）

### 3.2 タスク開始テンプレート

```md
## Task Brief
- Scope:
- Non-Goals:
- Acceptance Criteria:
  - [ ] ...
  - [ ] ...
- Checks:
  - [ ] tests/lint
  - [ ] docs sync
  - [ ] safeMode impact
```

### 3.3 受入条件の最低基準

- 仕様根拠（00〜02）を参照している。
- 差分が最小・可逆である。
- safeMode既定ONと漏えい防止を破らない。
- 参照導線の更新漏れがない。

## 4. 継続進行プロトコル

### 4.1 反復サイクル

Plan → Execute → Verify → Record → Continue

- Plan: 受入条件の先出し
- Execute: 単一スコープの変更
- Verify: 自動チェック + 目視
- Record: 変更点/未対応点/理由
- Continue: 未達条件があれば次タスク化

### 4.2 中断復帰時に必ず残す情報

1. 未完了の受入条件
2. 現在のブロッカー
3. 次の1手（再開コマンド / 編集対象）

### 4.3 優先順位

1. Security / safeMode
2. 上位層整合（00〜02）
3. 回帰防止（テスト）
4. 開発速度

## 5. リリース前チェック（AIエージェント）

### 5.1 必須

- [ ] 変更は宣言スコープ内
- [ ] 上位文書（00〜02）と矛盾なし
- [ ] safeMode既定ON・漏えい防止を維持
- [ ] 対象範囲のテスト/検証を実施
- [ ] AGENTS/README/対象文書の導線を整合

### 5.2 条件付き

- [ ] Schema変更: import/export/validation/testsを追随
- [ ] UI視覚変更: スクリーンショットを取得
- [ ] LLM経路変更: 外部送信設定・監査項目を確認

---

## 6. 停止・復旧・エスカレーション

### 6.1 停止基準

- 上位層（00〜02）との矛盾
- safeMode/漏えい防止への抵触
- 受入条件に対する重大未達

### 6.2 復旧手順

1. 差分をスコープ単位で切り戻す
2. 仕様根拠を再確認
3. 受入条件を再定義して最小修正で再開

### 6.3 人手エスカレーション条件

- 仕様変更そのものが必要
- 価値判断を伴うトレードオフ
- セキュリティ影響の確信が持てない

## 7. ツール固有追補（必要時のみ）

本書は共通運用を定義する。以下は必要時のみ上乗せする。

- **Antigravity固有**: タスク分解方法、成果物フォーマット、統合手順
- **Codex固有**: 実行環境制約、利用ツール、PR作成手順

共通規範（本書）とツール固有手順を混在させず、
固有事項は追補として明示分離すること。
