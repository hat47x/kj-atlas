# meta_prompt — 自律進行メタプロンプト

この文書は、課題が見当たらないときでも AI エージェントが停止せず、
**現在フェーズの判定 → 不足抽出 → 次フェーズ企画 → 並列化判断** を進めるためのメタプロンプトです。

他プロジェクト由来のショートハンド設計を取り込みつつ、kj-atlas 向けに **上位整合・安全優先・監査可能性** を前提として整理しています。

---

## 1. 前提

次の文書と矛盾しないこと。

- `AGENTS.md`
- `00_Prompt/system_prompt.md`
- `00_Prompt/agent_handover.md`
- `00_Prompt/codex_gsd_skill_ops.md`
- 必要に応じて `00_Prompt/virtual_stakeholder_consensus.md`

メタプロンプト由来の提案が上位文書（00〜02）と矛盾する場合は、実装ではなく **上位修正提案** を先に出します。

---

## 2. 使う場面

以下のショートハンドをそのまま受け付けます。

- 「現在のフェーズをクローズして」
- 「次フェーズを計画して」
- 「並列実行用プロンプトを作成して」
- 「開発を進めて」

ここで生成するのは、**実行計画または判定結果** であり、未承認の仕様決定そのものではありません。

---

## 3. 共通ルール

1. `AGENTS.md` から現在のタスクに必要な正本だけを読む
2. 00〜02 と 03〜04 の不整合を検知したら、下流実装より先に上流修正提案を出す
3. 「決定済み」「提案」「未確定」「実施済み」を混ぜない
4. 完了判定は、実行コマンド・差分・既存文書の根拠で示す
5. 人間判断待ち論点は `virtual_stakeholder_consensus.md` に引き渡す

---

## 4. コマンド別プロトコル

### コマンド1: 「現在のフェーズをクローズして」

1. 現フェーズの完了条件を抽出する
2. 実ファイル差分・検証結果・文書同期状況と突合する
3. 次の形式で出力する
   - 判定: `Close可` / `Close不可`
   - 理由: 3行以内
   - 未充足事項と次アクション（`Close不可` の場合のみ）

`Close可` の場合のみ完了宣言を行います。

### コマンド2: 「次フェーズを計画して」

1. 不足と上位要求を起点に、次フェーズの目的・成果物・Exit Criteria を設計する
2. 未確定論点がある場合は `virtual_stakeholder_consensus.md` の手順へ渡す
3. 結論のみを ADR / Issue / 運用文書へ反映し、議論の過程は必要時のみ分離する

### コマンド3: 「並列実行用プロンプトを作成して」

1. 編集ファイルが重複しないよう、ストリームを分割する
2. 各ストリームに次を明記する
   - 対象ファイル
   - 受入条件
   - 検証方法
   - 停止条件
3. 共有統合ファイルは最後の統合ストリームへ隔離する

出力テンプレート:

```text
#### [Stream A: 〇〇] 用プロンプト
Role: kj-atlas 実行エージェント
対象ファイル: [...]
タスクリスト:
- Task 1: ...
- Task 2: ...
指示: 直列実行し、各Task後に検証する。未達時は次へ進まない。
```

### コマンド4: 「開発を進めて」

1. まず「現在のフェーズをクローズして」を実行する
2. `Close不可` なら、不足タスク整理または並列実行計画を出す
3. 現行フェーズが閉じられる場合のみ、「次フェーズを計画して」へ進む

---

## 5. GSD運用（必要時のみ）

- GSD は実行管理の補助に限定し、仕様正本にはしない
- milestone → phase → verify の順で進める
- 各 phase で DoD / 受入条件 / verify結果 / 次 phase 開始条件を明示する

---

## 6. 標準出力フォーマット

1. 現在phase完了判定
2. 不足タスク一覧（最大10件）
3. 並列化または実行計画
4. 次phase企画（ADR下書きレベル）
5. 未確定論点
6. 直近アクション（次の1営業日で実施）

---

## 7. 禁止

- 仕様の独断追加
- SafeMode既定ONや漏えい防止を弱める提案
- エビデンスなしの完了宣言
- 未確定事項の確定扱い
