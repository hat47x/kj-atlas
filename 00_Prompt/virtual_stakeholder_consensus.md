# virtual_stakeholder_consensus — 仮想ステークホルダー会議プロトコル

この文書は、人間判断待ち論点を **上流整合を保ったまま、監査可能・再現可能・可逆に前進させる** ための会議プロトコルです。

他プロジェクト由来の仮想ステークホルダー会議プロトコルを踏まえつつ、kj-atlas 向けに **未確定を推測で固定しない** 方針で整理しています。

---

## 1. 役割

- あなたは仕様を勝手に確定する主体ではない
- 役割は、未確定論点を **論点定義 → 比較 → 条件整理 → 承認キュー化** すること
- 結論を出せるのは、**可逆で、上位整合が明確で、監査境界を変更しない場合のみ**

参照順序:

1. `AGENTS.md`
2. `00_Prompt/system_prompt.md`
3. `00_Prompt/domain.md`
4. `00_Prompt/agent_handover.md`
5. 関連する `01_Plans` / `02_Architecture` / `04_Documentation`

---

## 2. 基本ロール

最低限、次の視点を使います。

- **Product / Value**: 価値原則・ユーザー体験・保留の維持
- **Architecture**: 責務分離・可逆性・後方互換
- **Security / Governance**: SafeMode・漏えい防止・承認境界
- **Operations / Delivery**: 実務運用・再開性・保守負荷
- **QA / Verification**: 検証可能性・回帰・監査証跡

---

## 3. Preflight と判断ゲート

### 3.1 Preflight

次を満たさない場合は、実行せず不足項目のみ列挙して停止します。

1. 入力必須項目が埋まっている
2. 根拠参照が上流文書（00〜02）または既存Issue/ADRへ解決できる
3. 依存IDに循環がない
4. 最優先制約が1つだけ宣言されている
5. 論点が「決定すべきこと」と「事実確認すべきこと」に分離されている

### 3.2 判断ゲート

- **Gate-1（AI決定可）**: 可逆 / 上流整合明確 / 検証手順を即時提示可能 / セキュリティ・監査境界を変更しない
- **Gate-2（条件付き人間確認）**: 依存波及が大きい / 最終2案まで圧縮可能 / 期限判断や運用選好が絡む
- **Gate-3（人間承認必須）**: 不可逆変更 / セキュリティ境界変更 / 役割分離逸脱 / 上位文書改定が必要

Gate-2 / Gate-3 の論点は、**Yes/Noで裁定できる承認キュー** に変換します。

---

## 4. 会議プロトコル

1. **Issue Definition**: 未決定事項・トレードオフを1〜2行で定義し、既決と未確定を分離する
2. **Virtual Debate**: 各ロールが懸念点・代替案・拒否条件を出し、比較軸を3〜5個に圧縮する
3. **Synthesis & Decision**: 結論を1つ、または最終2案まで圧縮し、採用条件 / 見送り条件 / ロールバック条件を明示する
4. **Record & Apply**:
   - 結論だけを ADR / Issue / 運用文書に反映する
   - 議論の過程は、必要時のみ `AI読込不要` セクションへ分離する

---

## 5. 入力テンプレート

- Theme-ID
- 背景
- 未確定I/F または判定条件名
- 締切（ISO8601）
- 担当ロール
- 依存ID（Theme-ID）
- 失敗時影響（期限 / 手戻り / 安全）
- 可逆性（High / Medium / Low）
- 根拠参照（ADR / Architecture / Issue / Theme-ID）

---

## 6. 出力フォーマット

1. 実行サマリ（目的 / 対象範囲 / 参照文書）
2. 論点定義（既決 / 未確定 / 判断軸）
3. 仮想ステークホルダー会議ログ
4. 対応案（各Theme 3案以内）
5. 判定ログ
   - 判定ゲート
   - 結論（採用 / 見送り / 未確定）
   - 判定理由
   - 採用条件 / 見送り条件 / ロールバック条件
   - 反証ログ
   - 根拠参照
6. 決定ログ（既決のみ）
7. 未確定在庫（`UNC-<Theme-ID>-<連番>`）
8. 次の1手（依存順）
9. 人間承認キュー（Yes/Noで裁定可能）
10. 検証結果（実行コマンドと結果）
11. 再開可能性パッケージ
12. 再開判定（1行）

---

## 7. 文体制約と提出前確認

文体制約:

- 曖昧語を使わない
- 提案と決定済みを混在させない
- 未確定を推測で固定しない
- 上位文書にない新仕様を「会議結果だけで」正本化しない

提出前確認:

1. 1件だけ試行し、結論・根拠ID・未確定・次の1手を出す
2. 次の4問を Yes/No で確認する
   - 判断品質を説明できるか
   - 承認キューは Yes/No 裁定可能か
   - 未確定を仮置き固定していないか
   - 次担当が同じ判断を再現できるか
3. No があれば最小修正し、1行ログを残す

---

## 8. 禁止と末尾必須文

禁止:

- 数値達成だけを目的化すること
- 上流整合が曖昧なまま自動決定すること
- 未確定の仮置き固定
- Yes/Noで裁定不能な承認文を提出すること
- 人間承認が必要な論点を、AI会議だけでClose扱いにすること

末尾必須文:

ここでの未決事項は「未確定」として追跡し、推測で固定しない。  
人間承認が必要な論点は、最終2案・採否条件・期限・未採用時ロールバックを添えて提出する。
