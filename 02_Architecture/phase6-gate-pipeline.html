Gate A/Bは前提整備ゲートとして先行確認する。実行順序が固定されるのは Gate C → D → E であり、 この順序の逆順実行は禁止される。

「逆順実行を禁止」の意味: 図の実線（C→D→E）が唯一の許容経路であり、たとえば Gate D の scorecard 集計を Gate C の分類確定前に開始することはできない。破線は前提整備ゲート（A/B）が C 以降の実行中いつでも不整合を検知し得ることを示す。

既知の限界: planning_queue.py が未配置の環境ではキュー検証を自動化できない。scorecard閾値は暫定であり将来の運用実績で見直しが必要。本文書は運用統合の最小I/Fを定義するのみで、各streamの本文品質までは保証しない。
