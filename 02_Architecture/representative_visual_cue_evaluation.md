# 代表視覚手掛かり Phase 0 評価計画

## 1. 目的

本書は、`DOMAIN-VISUAL-CUE-01` の実装前に、代表視覚手掛かりが島の再発見を助けるか、意味の誤認や認知負荷を増やさないかを比較する最小評価計画です。

評価対象は、標準KJ法の手描きシンボルと連続する低コストな表現から始めます。生成AIの品質比較や画像の美しさは対象にしません。Phase 0で方向性を確認できない場合は、永続スキーマ、外部素材検索、画像生成へ進みません。

機械可読な代表場面の正本は `02_Architecture/design/representative_visual_cue/phase0_scenarios.json` とします。このJSONは評価入力であり、`DocumentV1` または将来の永続形式ではありません。

## 2. 比較条件

すべての条件で、島の位置、寸法、表札、要約、カード、色、表示時間を同じにします。異なるのは表札横の小さな手掛かりだけです。

| 条件 | 表示 | 検証すること |
|---|---|---|
| C0 文字のみ | 表札と短い説明 | 現行基準 |
| C1 手描きシンボル | 自由線、単色、短い文字から成る粗い印 | 標準KJ法に近い小さな印で十分か |
| C2 基本図形 | 円、矩形、三角、線、矢印など汎用図形の組合せ | ExcelやPowerPoint等の図形に近い表現で十分か |
| C3 利用者写真 | 利用者が撮影したfixture写真の切り抜き | 具体的な現場の再認識と原資料遡及を両立できるか |
| C4 絵文字・プリセット | Unicode絵文字または同梱候補 | 作成負担を下げても取り違えが増えないか |

外部素材と生成画像はPhase 0の対照候補として説明だけを残し、最初の比較には含めません。C0からC4で効果が確認できない場合、より複雑な経路を追加する根拠がないためです。

## 3. 代表場面

### VC-S1 具体的な窓口業務

8つの島から、「入口の案内表示」「本人確認」「例外対応」など指示された対象を順に探します。具体物と対応する手掛かりが、表札を読む時間を補助するか確認します。

### VC-S2 抽象的な対立

「速さを優先したい」「丁寧さを守りたい」「判断が割れている」を扱います。一つの具体物や感情へ決めつけず、中立的な印または画像なしを選べるか確認します。

### VC-S3 写真が一次資料

入口の案内板が照明を反射して読めない観察記録を扱います。写真の一部を手掛かりとして表示しても、元写真、撮影状況、観察カードへ戻れるか確認します。切り抜きだけを根拠として扱ってはいけません。

### VC-S4 機微情報

相談者の生活状況を含む未レビューの取材メモを扱います。外部通信のない条件だけを提示し、写真に人物や個人を推測させる情報を追加しないこと、画像なしで完了できることを確認します。

### VC-S5 似た記号の衝突

「窓口で待つ」と「職員の確認を待つ」のように、どちらも時計・砂時計へ寄りやすい島を扱います。記号の重複が表札の読み飛ばしや誤選択を増やさないか確認します。

## 4. 実施手順

1. 参加者へ「画像は分類、根拠、レビュー済み状態を表さない」とだけ説明し、個々の手掛かりの意味は教えません。
2. 練習用の対象を一つ探してもらい、選択方法だけを確認します。
3. VC-S1からVC-S5について、画面上部に一つの探索指示を表示し、正しい島を選ぶまでの時間と誤選択を記録します。
4. C0からC4の提示順は参加者ごとに入れ替え、学習順の影響を一つの条件へ偏らせません。
5. 各条件の直後に「探しやすかったか」を5段階で一問だけ尋ねます。自由記述は任意とし、回答を強制しません。
6. VC-S2では、画像が対立の解決や多数意見を意味するかを確認します。VC-S3では、元写真と撮影状況へ戻ってもらいます。
7. 最後に、画像なしを常時選べること、手掛かりを変更・削除しても内容が変わらないことを確認します。

評価は方向性を確認する小規模pilotとし、統計的な製品効果を主張しません。まず3人以上の代表利用者で、操作理解と重大な誤認の有無を確認します。対象利用者を確保できない場合、実装担当者だけの結果を利用者評価として扱わず、操作fixtureの予備確認に留めます。

## 5. 記録項目

| 項目 | 記録方法 | 意味 |
|---|---|---|
| 発見時間 | 指示表示から正しい島の選択までのミリ秒 | 再発見の速さ |
| 誤選択数 | 正解前に選んだ別の島の数 | 取り違え |
| 探しやすさ | 1（探しにくい）から5（探しやすい）の一問 | 主観的負担の軽量な補助 |
| 意味誤認 | 分類、根拠、解決済み、人物属性と誤解したか | ドメイン境界の安全性 |
| 原資料遡及 | VC-S3で元写真、撮影状況、観察カードへ到達できたか | 一次視覚資料の保持 |
| 操作不能 | 入力手段、画面幅、読み上げで完了できなかった箇所 | UQ-1/UQ-2/UQ-4 |

顔映像、音声、自由記述の生データを既定で収集しません。参加者IDは評価内の仮名とし、結果共有では個人別の速さを順位付けしません。

## 6. 判定

### 即時停止

次のいずれかが一件でも起きた条件は、標準候補へ進めません。

- 手掛かりを事実、根拠、レビュー済み、対立解消済みと誤認する。
- 元情報にない人物属性、感情、因果関係を読み取らせる。
- VC-S3で切り抜きから元資料へ戻れない。
- VC-S4で外部通信または未レビュー情報の共有を必要とする。
- 画像を非表示にすると操作または内容理解を完了できない。

### 次段階へ進む目安

- C1からC4の少なくとも一条件が、C0より誤選択を増やさず、5場面中3場面以上で発見時間または探しやすさの改善傾向を示す。
- 参加者が手掛かりと表札を併用し、手掛かりだけで判断しない。
- 手描き・基本図形の作成負担が、プリセットを探す負担より明らかに高い場合は、描画機能を増やさずプリセット優先も選べる。

この目安は有意差や一般的効果を主張する基準ではありません。条件間の差が小さい場合は、通信・権利・保存負担が最も小さい条件を優先します。

## 7. 証跡

最低限、次を同じ評価日・同じfixture版に結び付けます。

- fixture versionと対象commit。
- 条件ごとの集計値と重大な誤認。
- マウス、キーボード、390pxの操作trace。
- C0、採用候補、停止候補の画面キャプチャ。
- 次段階へ進むか、要件を修正するか、実装しないかの判断理由。

個人別の詳細記録や画像を公開文書へ掲載しません。製品機能として採択するまでは、`04_Documentation` に利用可能な機能として記載しません。
