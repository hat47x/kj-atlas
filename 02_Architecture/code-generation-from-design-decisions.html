設計判断からのコード生成仕様

区分: 設計ビュー / 更新: 2026-08-08 / 正本: ADR-0067
用途: 三要素整合が確認された設計判断から、実装コードを自動生成するための仕様。 生成AI（L3自律性レベル）がこの仕様に従ってコードを生成する。

前提: この仕様で生成対象とする設計判断は、三要素整合チェックリスト （three-element-constraint-checklist.html）の全18項目に合格したものだけである。 三者が揃っていない設計判断からのコード生成は行わない。

3.3 生成プロンプト（AIエージェント向け）

# Task: Generate code for new AI task "{taskName}"

## Design Decision (three-element verified)
{designDecision}

## Instructions
1. Read the existing patterns from the codebase:
   - Backend model pattern: read models_ai.py RefineCardTextRequest/Response
   - Backend route pattern: read routes/ai.py refine_card_text endpoint
   - Frontend client pattern: read client.ts suggestLayout function
   - Test pattern: read test_llm_provider.py

2. Generate each file following the EXACT same structure as the pattern,
   substituting only the task-specific names, fields, and types.

3. Add imports to existing import blocks (do not create new import sections).

4. Validate by running:
   - python -m py_compile on each modified .py file
   - python check_contract_drift.py
   - python check_design_consistency.py

5. Do NOT create new architectural patterns. Follow existing conventions strictly.

## Constraints
- SafeMode: filter unreviewed card text before sending to AI
- Proposal-only: output is suggestion, human must adopt
- No scoring/ranking in output format
- All new env vars must be registered in runtime_parameter_registry.md

4. 生成パターン: 新規UIコンポーネント

ui_component型（DX-CODEGEN-01でジェネレータ実装済み）。三要素整合確認済みの設計判断からReactコンポーネントの骨格を生成する。

4.1 生成されるファイル

#ファイル生成内容
1ui/{ComponentName}.tsxReactコンポーネント（props型 + ロジック + JSX）
2i18n/locales/ja.json日本語メッセージキー（コンポーネント名をプレフィックスに）
3i18n/locales/en.json英語メッセージキー
4App.tsximport追加 + コンポーネント統合（最小差分）

4.1a 入力形式（ui_component型）

{
  "designDecision": {
    "type": "ui_component",
    "componentName": "CardQualityAssist",
    "description": "カード品質自己チェック表示",
    "pattern": "basic",        // "basic" | "form" | "list"（DX-CODEGEN-02）
    "props": [
      {"name": "cardId", "type": "string"},
      {"name": "onApply", "type": "() => void"}
    ],
    "i18nKeys": ["card_quality.title", "card_quality.apply"],
    "testIds": ["card-quality-panel", "card-quality-apply"]
  },
  "threeElementVerification": { "business": "...", "data": "...", "function": "..." }
}

4.1b ロジック生成パターン（DX-CODEGEN-02）

patternフィールドでJSXロジックの生成を選択する。骨格生成（DX-CODEGEN-01）を超えて、共通UIパターンのロジックを自動生成する。

pattern生成されるJSXロジック実装状態
basic骨格のみ（props型・data-testid・i18nキー）。後方互換✅ DX-CODEGEN-01
formtextarea + onChange + 保存/キャンセルボタン + Escape/Ctrl+Enter（document_titleパターン準拠）✅ DX-CODEGEN-02
listitems.mapリスト表示 + 追加ボタン✅ DX-CODEGEN-02

4.1c 既存実装チェック（DX-CODEGEN-01改善）

生成前に既存実装を検出し、重複コードの生成を防止する。

  • ファイル名完全一致: 対象.tsxが既に存在すれば生成を拒否
  • トークン部分一致: BulkReasonEditor → BulkOperationsBar（"Bulk"トークン）等を検出して拒否
  • 汎用トークン（Editor/Component/Panel等）は除外して誤検出を防止
  • data_boundary型はクラス存在チェック

4.2 制約

  • コンポーネントは純粋関数コンポーネント。class component不可
  • スタイルはinline styleオブジェクト（CSS-in-JSパターン）。外部CSSファイルを作らない
  • i18nキーはコンポーネント名をプレフィックスに（例: document_title.*）
  • 初期表示への純増禁止。既存要素の置換・包含・モード分離で収める
  • data-testid属性を主要要素に付与
  • Escapeによる段階閉鎖、triggerへのfocus復帰、キーボード到達性を維持
  • 生成は三要素整合チェックを通過した設計判断のみ。出力はレビュー後に手動適用（proposal-only）

5. 生成パターン: データ境界変更

data_boundary型（DX-CODEGEN-01でジェネレータ実装済み）。三要素整合確認済みの設計判断からPydanticモデル骨格と契約追記を生成する。

5.1a 入力形式（data_boundary型）

fieldsに検証ルール（minLength/maxLength/pattern/default）を宣言すると、PydanticのField(...)制約として生成される（DX-CODEGEN-02）。

{
  "designDecision": {
    "type": "data_boundary",
    "typeName": "FieldworkRequestV1",
    "description": "W型累積KJ法の現場への問い",
    "saveScope": "document",
    "fields": [
      {"name": "id", "type": "str", "minLength": 1, "maxLength": 64},
      {"name": "question", "type": "str", "minLength": 1, "maxLength": 500},
      {"name": "resolved", "type": "bool", "default": "False"},
      {"name": "note", "type": "str | None", "default": "None"}
    ]
  },
  "threeElementVerification": { "business": "...", "data": "...", "function": "..." }
}

生成されるPydanticモデル（検証制約付き）:

class FieldworkRequestV1(BaseModel):
    """W型累積KJ法の現場への問い — document 保存."""
    model_config = ConfigDict(extra="forbid")

    id: str = Field(min_length=1, max_length=64)
    question: str = Field(min_length=1, max_length=500)
    resolved: bool = Field(default=False)
    note: str | None = Field(default=None)

6. CI統合

コード生成後、以下のCIチェックが自動実行される（ci.yml に設定済み）:

  1. check_design_consistency.py — ADR/API/スキーマ参照整合
  2. check_contract_drift.py — 実装↔契約の乖離検出
  3. frontend typecheck + test — TypeScript型チェック + Playwright e2e
  4. backend lint + test — pytest + 契約テスト
